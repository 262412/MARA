# MARA Desktop 界面与交互规范

## 1. 设计原则

1. **MARA 工作流优先**：信息架构借鉴 Codex，功能和术语来自 MARA。
2. **证据始终可达**：答案、引用、原文和运行状态之间最多一次操作切换。
3. **桌面密度，不做移动放大版**：利用宽屏，但不依赖超宽屏。
4. **渐进展示复杂度**：默认只显示当前任务需要的控制，高级参数进入检查器。
5. **可恢复比“看起来很快”重要**：长任务必须显示阶段、取消和恢复状态。
6. **本地感知**：文件、路径、存储、模型和网络状态都清楚可见。

设计检索中出现的“移动应用商店落地页”和“仅 OLED 深色”模式不适合本产品，
因此不采用。保留其可访问性建议：可见焦点、完整键盘路径、明确 active 状态、
异步加载反馈和 reduced-motion 支持。

## 2. 桌面信息架构

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 原生 Windows/Linux 标题栏                                                  │
├──────────────┬──────────────────────────────────────┬───────────────────────┤
│ 左侧导航     │ 任务工具栏                           │ 检查器标签            │
│ 240–280 px   ├──────────────────────────────────────┤ Preview Sources Run   │
│              │                                      ├───────────────────────┤
│ + 新建任务   │ 对话 / Studio / 图谱主工作区         │ 文档、证据、任务阶段  │
│ 工作台       │                                      │ 380–560 px            │
│ Files        │                                      │                       │
│ Resources    │                                      │                       │
│              ├──────────────────────────────────────┤                       │
│ 最近任务     │ 来源胶囊 + 输入框 + 模型/模式 + 发送 │                       │
│              │ Composer 固定在底部                  │                       │
│ Settings     │                                      │                       │
└──────────────┴──────────────────────────────────────┴───────────────────────┘
```

采用原生系统标题栏，不复制 macOS “红黄绿”窗口按钮。Windows/Linux 的窗口
移动、缩放、最大化和辅助技术兼容由系统负责；应用工具栏位于原生标题栏下方。

### 响应规则

| 窗口宽度     | 行为                                           |
| ------------ | ---------------------------------------------- |
| ≥ 1440 px    | 三栏全部展开；检查器默认 440 px                |
| 1180–1439 px | 三栏；左栏 240 px，检查器 380 px               |
| 1024–1179 px | 左栏压缩；检查器以覆盖层或手动打开             |
| < 1024 px    | 非目标工作区；显示最小尺寸提示，不做移动端重排 |

最小支持窗口为 1024 × 720。面板宽度在有效范围内持久化，但跨显示器恢复时
必须重新约束，不能把主内容挤出屏幕。

## 3. 各区域职责

### 左侧导航

- 品牌与当前数据空间。
- “新建任务”主操作。
- 工作台、Files、Resources、Help 的一级入口。
- 最近任务：标题、状态、来源数量；支持固定、重命名和删除。
- 底部账户/本地模式状态与 Settings。

左侧导航不承载模型参数、文档预览或运行日志，避免成为无边界抽屉。

### 中间工作区

- 任务标题、来源摘要和任务级操作。
- 对话消息、知识图谱或 Studio 工作区，根据当前模式切换。
- 答案中的引用编号可聚焦、可用键盘激活。
- 底部 Composer 包含添加来源、执行模式、模型路由、停止/发送。
- 长输出使用内容骨架和阶段文案，不让输入区随内容跳动。

### 右侧检查器

- **Preview**：原文件和当前页；引用跳转后高亮证据。
- **Sources**：当前任务来源、选择状态、索引状态和证据片段。
- **Run**：检索、生成、artifact 等阶段状态和可公开诊断。
- **Notes/Studio** 可在有内容时成为上下文标签，不固定占用一级导航。

检查器可以关闭；关闭后点击引用必须自动重新打开到 Preview。

## 4. 视觉系统

### 深色令牌（默认）

| 角色               | 值        | 用途               |
| ------------------ | --------- | ------------------ |
| `--bg-app`         | `#111312` | 最外层炭黑背景     |
| `--bg-sidebar`     | `#151817` | 导航与检查器       |
| `--bg-panel`       | `#1A1D1C` | 主工作区           |
| `--bg-elevated`    | `#202422` | 卡片、选中任务     |
| `--bg-subtle`      | `#232725` | 次级控制和 hover   |
| `--text-primary`   | `#ECEFED` | 主文本             |
| `--text-secondary` | `#9AA39F` | 辅助文本           |
| `--border`         | `#303734` | 分隔线             |
| `--accent`         | `#70B89C` | 低饱和 MARA 薄荷绿 |
| `--accent-strong`  | `#8BCBB1` | active/pressed     |
| `--focus`          | `#78A9E6` | 键盘焦点环         |

PDF/Office 的原始页面使用文档自身背景，不做强制反色。浅色作为可选主题保留，
两套主题都必须达到正文 4.5:1、较大文本 3:1 的对比度要求。

配色调研依据：

- [OpenAI Appearance 设置](https://learn.chatgpt.com/docs/reference/settings#appearance)
  把 base theme、accent、background 和 foreground 分开配置，因此 MARA 也使用
  独立语义令牌，而不是一组颜色整体写死。
- [Linear 2026 设计刷新](https://linear.app/now/behind-the-latest-design-refresh)
  从偏冷蓝转向更温暖、低饱和且仍清晰的灰色；MARA 采用相同的克制原则。
- [Cursor 官方桌面展示](https://cursor.com/)使用低噪声纯色层级承载高密度任务状态，
  不依赖大面积渐变或发光。

### 字体与尺寸

- 字体使用系统 UI 字体栈，离线运行，不从 Google Fonts 或其他 CDN 加载。
- 正文 14 px / 1.55；辅助 12–13 px；页面标题 18 px；不使用大面积 32 px 标题。
- 间距使用 4 px 基准：4、8、12、16、24、32。
- 圆角：控件 8 px，卡片 12 px，Composer 14 px；避免所有元素都做药丸形。
- 动画 120–180 ms；尊重 `prefers-reduced-motion`。

## 5. 状态设计

每个异步组件都必须覆盖：

- `idle`：可执行。
- `queued`：进入后台队列。
- `running`：显示阶段、已耗时和取消。
- `partial`：已有可用结果，但任务未完整完成。
- `success`：明确输出和下一步。
- `failed`：用户可理解的原因、诊断详情和重试。
- `cancelled`：保留已产生内容，标记未完成。
- `offline`：指出受影响能力，不把全部页面禁用。

按钮同时具有 default、hover、active、focus-visible、disabled 和 loading 状态。
颜色不是状态的唯一载体。

## 6. 键盘与无障碍

| 快捷键         | 行为                                 |
| -------------- | ------------------------------------ |
| `Ctrl+N`       | 新建任务                             |
| `Ctrl+O`       | 添加本地文件                         |
| `Ctrl+K`       | 打开任务/命令搜索                    |
| `Ctrl+L`       | 聚焦 Composer                        |
| `Ctrl+Shift+P` | 显示/隐藏右侧检查器                  |
| `Ctrl+,`       | 打开 Settings                        |
| `Esc`          | 关闭覆盖层；运行中再次确认后停止任务 |

- Tab 顺序与视觉顺序一致，并提供“跳到主工作区”链接。
- 面板、标签和导航使用正确语义与 `aria-current` / `aria-selected`。
- 引用、文件和图节点不能只通过 hover 才可发现。
- 缩放 200% 时核心流程仍可用，不出现不可达控件。
- 拖放必须有等价的键盘文件选择操作。

## 7. 正式视觉设计待确认项

在进入高保真前只保留以下可调项，不重新讨论已冻结架构：

- MARA 品牌绿色的最终色值和应用图标。
- 左栏宽度、消息最大宽度和检查器默认宽度。
- 任务项的信息密度与状态图标。
- Preview、Sources、Run 标签的排序和显隐。
- 浅色/深色主题的层级和文档预览背景。

每次微调必须用同一组基准场景比较：空状态、长对话、引用跳转、索引进行中、
Studio 产物和运行失败。
