\section{Recorded Diagnosis and Targeted Repair}
\label{sec:case}
We examine what the records reveal beyond the displayed answer, then test a repair. The Harbor task uses two author-constructed documents about a fictional sensor pilot, executed with real APIs. The operating guide refers to a separate policy; that policy specifies a 17-day raw-log retention period. These new deployment records are separate from the historical benchmark.

\paragraph{A raw-answer baseline matters.}
With only the operating guide selected, the original model already explains that the duration is absent and points to the policy. Preserving that explanation is sufficient to suggest source reselection, a capability inherited from Kotaemon. LMDoc's generic final refusal obscures this useful explanation. We therefore do not count finding the missing policy as evidence of superior diagnosis. The additional records instead locate the transformation: retrieval is \texttt{good}, generation completes, verification is \texttt{unknown}, and the guardrail abstains. Table~\ref{tab:boundary} compares the saved observations without inferring a user advantage.

\paragraph{A supported answer is falsely rejected.}
Selecting the policy yields a cited 17-day answer in the original run. A retained independent repetition instead rejects the extra explanation that logs are deleted after that period and that the policy applies to Harbor raw logs. Both statements are supported by the supplied policy. This is a verifier false rejection, not an unsupported model answer. Inspecting its claim record and lexical matcher identifies the cause: eight of twelve content tokens match, below the nine required, because \emph{delete} and \emph{deleted} are treated as different words. Raw answer and evidence alone expose the incorrect rejection; the stage record and source replay identify the responsible check.

\paragraph{Repair and bounded verification.}
A small patch matches regular \emph{-d/-ed} variants while retaining the coverage threshold and numerical/negation conflict checks. Replaying the identical recorded claims changes verification from unsupported to supported; wrong-duration and negated controls remain rejected. We then execute five predeclared source pairs with the patched source: all policy-selected turns return the supported duration, and all operating-guide-only turns abstain. The unpatched verifier also accepts the five newly generated policy answers in an identical-claim replay. Thus the controlled replay establishes the specific repair; these fresh runs show successful execution but do not establish a general reliability gain. The supplementary patch and all outcomes are retained. No timed participant task or matched upstream run has been conducted.

\paragraph{Visual evidence changes an answer.}
A second case asks for the pink curve's rightmost value on a public Arctic sea-ice chart (Figure~\ref{fig:diagnosis}). Auto selects text and answers approximately $-50\%$. The record shows a text-provider call and no image input. Manually selecting the page-image route sends the rendered page to the same model and returns approximately $-40\%$, consistent with the plotted endpoint. Removing only the image from that captured generation request yields $-50\%$ again. This single component ablation demonstrates an observed image-dependent answer, not general visual accuracy. The intervention is manual, not an automatic recovery switch. Both runtime conditions disable verification to isolate generation; the local image selector searches one preselected page.

\paragraph{Audit boundary.}
The package preserves requests, effective settings, evidence, raw provider outputs, intermediate and displayed answers, and decision traces. Its offline checks recompute declared outcomes from saved strings; a separate live script calls actual providers. These records support diagnosis of the new cases only. Historical SlideVQA generation strings and executed paths remain unavailable, so neither this repair nor a new visual case establishes the cause of its equal scores. Appendix~\ref{app:followup} gives execution identities, controls, and retained failures.
